# A-B 단면의 지형 상태 분류

## 원인

기존 `analyzeSection()`은 샘플마다 `inLand()`를 읽고 false면 `depthQuery() || modelDepth()`를 넣었다. `inLand()`는 해안선과 STRUCT를 보지만, 지도에 별도로 그리는 OSM `br`(bare_rock)와 ROCKS 위치점은 포함하지 않았다. ROCKS는 `classifyShore()`에서 첫 해안의 추정 경사를 고르는 데만 사용됐다. 따라서 지도에는 암반이 보여도 해당 샘플은 수심/추정 수심을 받아 그래프가 계속 연결됐다.

기존 샘플 생성은 모든 `land` 전환을 검사하므로 “첫 교차 이후 전부 바다” 가정은 없었다. 다만 실제 선분-다각형 교차 없이 샘플점의 land 변화만 보므로 샘플 사이의 작은 형상은 빠졌다. `profileFeatures()`와 해안 종류 자동 선택은 첫 해안의 연속 바다 구간을 분석하며, 이를 전 구간의 표면 분류로 재사용하지 않는다.

## 분류

`17b_section_surface.js`의 `sectionSurfaceContext()`가 A-B 선과 형상을 교차해 모든 표면 구간을 만들고, `classifySectionSample()`가 각 샘플의 상태를 결정한다. 판정은 지도 확대/이동이나 SDK에 의존하지 않는다.

우선순위:

1. **breakwater**: STRUCT의 실제 선·다각형, OSM 방파제·도류제·부두·안벽·방조제. 선형 자료는 기존 `inStruct()`와 같은 반폭 4m corridor 및 끝점 원을 사용한다. 다각형은 경계를 그대로 사용하고 OSM 구멍을 보존한다.
2. **rock_exposed**: OSM bare_rock 다각형. 선/점뿐이면 반폭/반경 1m의 최소 위치 corridor다. ROCKS 갯바위 포인트는 면적 자료가 아니므로 반경 2m만 보수적으로 제외하며 `point_location_only`로 범위 불확실성을 기록한다. 백사장/모래사장 이름의 낚시 포인트는 암반으로 만들지 않는다.
3. **land**: 전체 해상도 해안선의 짝홀 다각형 판정. 구멍 및 여러 섬을 처리한다.
4. **unknown**: 노출 여부를 확인할 수 없는 암초/사주/갯벌 형상, 또는 유효 수심을 얻지 못한 위치. 주변 수심이나 추정값으로 덮어 연결하지 않는다.
5. **water**: 위 차단 구간 밖에서 기존 수심 경로의 유효한 유한값을 얻은 위치. KHOA/GEBCO와 기존 해안 추정의 수치·estimated·datum/provenance를 그대로 보존한다. 실제 수심이 아닌 해안 추정은 계속 추정으로 표시한다.

항 중심점(PORTS)은 항의 면적/육상 경계가 아니므로 육지 판정 buffer로 사용하지 않는다. GEBCO 460m 격자로 작은 갯바위의 노출 면적을 만들어내지도 않는다. 원자료 좌표는 이동하지 않는다.

샘플 예:

```js
{
  distanceM: 115,
  lon: 128.001,
  lat: 36,
  state: 'rock_exposed',
  depthM: null,
  r: null,
  classification: {source: 'OSM:br', bufferM: 0, confidence: 'geometry'}
}
```

기존 `mx/my/s/land/dG/r`는 호환용으로 남긴다. `land`는 육상·구조물·암반에서 true이고, 수심 소비자는 `sectionSampleIsWater()`로 유효한 바다만 읽는다.

## 다중 전환과 짧은 형상

모든 교차 매개변수를 모아 `SEC.surfaceIntervals`에 시작/끝 거리와 상태·출처를 기록한다. 샘플점 상태의 변화는 `SEC.transitions`에 별도로 남긴다. 형상이 두 샘플 사이에만 있어 양쪽 점이 water여도 `blockedEdges`가 연결을 막는다. 샘플을 엉뚱한 위치의 암반으로 바꾸거나 비수중 깊이를 보간하지 않는다.

샘플 수 공식은 변경하지 않았다. 기존 기본 301개(300구간)와 긴 단면의 기존 적응형 정책을 그대로 두며, 작은 형상을 잡기 위해 샘플 수를 늘리지 않는다.

## Renderer

수심 선과 해저 채움은 연결 가능한 water run별로 그린다. 비수중 구간은 고도를 만들어내지 않고 육상/구조물/암반/미확인 띠로 표시한다. 수면선·캐스팅 안내·특징 분석도 차단 구간을 건너 연결하지 않는다. hover는 샘플 사이의 짧은 교차 구간도 읽는다. 수심 최대값/측정 비율은 water만 집계한다.

연속 run과 차단 edge는 단면 생성 시 계산해 프레임마다 형상 교차를 반복하지 않는다. 단면 그래프는 여전히 기존 자료 기준면을 사용하며 조위를 수심에 합치지 않는다.

## 검증

- 이전 실제 빌드 `6264889`에서 바다→갯바위→바다가 water로 남는 실패를 같은 테스트로 재현했다.
- 모바일 390×844와 PC 1280×900에서 12시나리오: 전부 바다, 바다→육지, 바다→갯바위→바다, 바다→방파제→바다, 육지→바다→육지, 샘플 사이 20cm 암반, 갯바위 위치점, 암초 노출 미확인, 다각형 구멍, 겹친 지형 우선순위, 경계와 나란한 단면, 수심 자료 없음.
- 각 케이스는 301개 샘플, 비수중 r/depthM null, 실제 Canvas 수심 stroke가 차단 구간을 건너 연결하지 않음을 검사한다.
- 순수 바다의 301개 좌표·수심 결과 전체(기준면/출처 포함)와 실제 Canvas 수심 경로가 이전 빌드와 정확히 같다.
- 원본 `p3_baseline.json`은 재생성하지 않았다. 새 상태 메타데이터를 제외한 기존 필드 전체로 비교한 원본 section hash `b682794bd45b25bda79f78ec05e290948b07bb75338bc7c076da4746a36db6af`가 동일하다.
- 이번 요청이 단면 엔진/renderer 변경을 명시적으로 허용하므로 production guard에서 `18_section.js`만 허용했다. `static/depth/`, `04_depth.js`, `04b_depth_tiles.js` 보호는 유지하고 `data/` 보호를 추가했다.

## 한계

위성영상 자체를 자동 판독하지 않는다. 기존 해안선/OSM에 형상이 없고 갯바위 위치점만 있는 곳은 실제 암반 면적을 복원할 수 없다. 작은 위치 buffer는 이 한계를 감추기 위한 면적 추정이 아니며 hover에 범위 미확인을 표시한다. 조석에 따라 잠기는 암초/갯벌은 노출 암반으로 단정하지 않는다.
