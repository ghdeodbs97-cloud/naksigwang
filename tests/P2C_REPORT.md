기준 main: `9143465`. 브랜치: `feat/p2c-khoa-depth`. main에는 직접 작업하거나 병합하지 않는다.

## 실제 호출 결과 (2026-10-11)

공식 endpoint `https://apis.data.go.kr/1192136/waterDepth/GetWaterDepthApiService`, `type=json`, 환경변수 `KHOA_SERVICE_KEY`만 사용했다. 요청 URL/키/인증 헤더는 저장하지 않았다.

| 영역 | bbox xmin/ymin/xmax/ymax | 최초 검사 | 전체 수집 | 전체 호출 수 |

| 거진 | 128.450 / 38.430 / 128.480 / 38.455 | A: NORMAL_SERVICE, totalCount 218, 10건/1회 | 218 | 1 |
| 주문진·남애 | 128.7 / 37.8 / 128.95 / 38.0 | 전체 페이지 수집 | **11,018** | **37** |

주문진·남애는 300건 × 36페이지 + 마지막 218건. 모든 전체 수집에서 `receivedCount=totalCount=uniqueCount`, 중복 0건, 재시도 0회였다. 전체 수집 40회 + 북쪽 최초 probe 3회 = **실제 호출 총 43회**, production 점 **11,702개**. probe의 30점을 중복 탑재하지 않았다.

**북위 38도 이상 실제 호출 성공**: 위 세 bbox에서만 확인했다. 다른 북쪽 영역/전국 지원을 확정하지 않으며 38도 상한 제한을 코드에 넣지 않았다. 웹 UI의 제한과 가이드 샘플의 불일치 원인은 아직 미확인이다.

각 정상 응답 header·원본 hash·bbox·수집시각·건수·호출 수는 [수집 감사 기록](p2c_khoa_collection_audit.json). 원 API의 실제 항목은 `lat/lot/dpwt`이며 `lot→lon`, `dpwt→depth`로만 매핑했다.

## 실제 파일·모바일 비용

- 원본: `tools/depth-data/raw/khoa/`의 **50파일 / 1,678,680 bytes**, Git 제외. 43개 응답 텍스트와 7개 수집 메타/정규화 파일이다. 미설정 상태에서는 호출하지 않았고 실패/가짜 원본을 만들지 않았다.
- 앱: `static/depth/` **11파일 / 455,007 bytes**. manifest 10,642 bytes + 타일 10개 444,365 bytes. 최대 타일 157,257 bytes, 자료집 4개.
- 처음에는 manifest만 요청하고 viewport/단면 인근 타일만 읽는다. 기존 12타일/60,000점/JSON 8 MiB 캐시 제한·퇴거 유지. 이 수치는 전체 JS heap 보증이 아니다. 실제 저사양 휴대폰 heap/프레임 측정은 미실시.
- 기존 GEBCO 파일과 운영 `data/*.json`은 변경하지 않았다. 합성 점은 mock route/임시 폴더에만 있고 production 점은 실제 API 응답에서 왔다.

## 동일 좌표 비교

저장소 실제 포인트/OSM 항 위치에서 가장 가까운 실제 KHOA 격자점을 골랐다. 기존 수심은 기준 main `9143465`의 앱을 메모리에서 실행해 **KHOA 격자점과 동일한 좌표**에서 조회했다. 아래 거리는 기준 낚시 포인트에서 KHOA 점까지이며 두 수심 조회 간 좌표 차이는 0 m다. 차이 = KHOA − 기존. 소수는 API 원값/회귀 비교용이지 제품 정확도 보증이 아니다.

| 지역 | KHOA 점 lat/lon | KHOA m | 기존 m | 차이 m | 기준점→KHOA m |
|---|---|---:|---:|---:|---:|
| 주문진 | 37.8920 / 128.8312 | 4.81 | 4.19 | +0.62 | 11.80 |
| 남애 | 37.9411 / 128.7894 | 6.69 | 10.56 | −3.87 | 78.18 |
| 아야진 | 38.2719 / 128.5569 | 4.47 | 1.74 | +2.73 | 71.57 |

| 거진 | 38.4431 / 128.4563 | 2.71 | 5.09 | −2.38 | 51.22 |

기존 다섯 값은 모두 `model_estimate / unknown`, KHOA는 `국립해양조사원 자연과학용 수심정보 / 평균해면하`. **기준면이 동등하게 보정된 비교가 아니며 수직 정확도 향상의 증거가 아니다.** 기존 GEBCO/모델 식은 바꾸지 않았다. [정밀 비교 JSON](p2c_khoa_comparison.json), [탑재 후 원 dpwt 일치 확인](p2c_khoa_integration.json).

## 출처·기준면·앱 연결

기존 P2B v1 출처사전/타일 형식을 유지했다. `sourceType:khoa`, source, datasetId, coverageBBox, 원본 수집 hash/시각/필드 매핑, `resolution:150`을 보존한다. 조사연도는 API에 없으므로 null. `verticalDatum:평균해면하`는 **사용자가 제공한 공식 조회 UI 원문**을 그대로 보존했다. API 응답 자체에는 기준면 필드가 없으며 이 작업에서 별도 활용가이드와의 일치까지 독립 확인하지 못했다. `MSL/DL/LAT` 등으로 임의 번역하거나 다른 기준면과 혼합하지 않았다.

[공식 안내](https://www.data.go.kr/data/15142498/openapi.do)는 수심측량자료를 이용해 제작한 **150 m 간격 해양수치모델용 데이터**라고 설명한다. 원본 측심 실측/정확도 보증으로 표시하지 않도록 `estimated:true`, 신뢰도 최대 중간, 상세 설명을 적용했다. 이용조건 공공누리 제1유형과 실제 수집 범위를 기록 탭에 표시했다.

KHOA는 기존 BADA 계층에서 GEBCO/모델보다 우선한다. 출처유형·자료집 ID를 유지해 다른 BADA/기준면과 합치지 않는다. 후보 반경 225 m, 육지 통과 제외, 최대 6개 동일 자료집/기준면 후보를 유지한다. **요청 bbox 안이면서 유효 후보의 볼록껍질 내부**에서만 기존 IDW를 사용해 가장자리 밖 외삽을 막는다. 정확한 원 격자점에서는 원 dpwt를 사용한다. 조건 미달이면 fallback한다. 이는 자료 없는 해역을 새 모델로 채우는 작업이 아니다. 해안선 오류·작은 격자 누락과 실제 서비스 coverage를 완전히 검증했다는 뜻도 아니다.

지도 조회/단면 엔진과 기본 수심·출처·신뢰도 표시를 유지했다. 단면 캐스팅/hover에도 KHOA 출처를 보존하고 기술정보는 기존 상세보기로 둔다. 사용자 설정/서버/새 가짜 수심 모델은 추가하지 않았다.
