# 입질 조건점수 V2.1 보고서

기준 코드: `993805e67cb1c9aeb3a0faba4e2ad8193a7c3677`. 기존 feat/p3-map-foundation / PR #6에서 작업하며 새 브랜치·PR·merge는 하지 않는다.

검사 자료는 체크아웃의 meta.generated=2026-10-25T07:34+09:00, DAY0=2026-10-25이다. 실행 시계를 이 시각에 고정해 동일 자료로 전후 비교했다. 현재 날짜(10월 31일)의 새 실시간 수온/예보라고 주장하지 않는다. data/*.json은 수정하지 않았다.

## 1. 날짜별 반복 점수의 원인과 실제 버그 여부

V2에서 날짜 키가 잘못 고정되었다는 증거는 없었다. BITE_CONTEXTS는 위도·경도·조석 지점·day·hour를 포함하고, wxAt은 DAY0+day의 날짜 키와 당일 시간 슬롯을 찾는다. tideAt/flowU에는 day×24+hour+0.5가 전달되고 crntAt/crntDay는 CR_OFF로 예보 기준일에 맞춘다. 이 경로는 수정하지 않았다.

반복의 실제 원인은 (1) 같은 포인트의 계절·권역·수심·지형과 같은 시각의 빛 조건이 거의 고정됨, (2) 동해 대표점은 실제 조류 예보가 없어 유속 기여가 0이고 작은 조석 영향만 있음, (3) 노래미·방어 등은 수온 모델이 미설정되어 기여 0, (4) 기상 차이가 작거나 먼 날짜의 예보가 누락됨, (5) 원점수 차이가 정수 반올림에 묻힘이다.

|---|---|---|---|---|
| 원점수 | 71.9133 | 71.0245 | 70.9710 | 71.2757 |
| 카드 점수 | 72 | 71 | 71 | 71 |

원본의 day0~3 전체 39종 factor 분해는 bite_v21_before.json에 season/region/depth/habitat/target/light/temperature/current/tide/wind/wave/catch로 보존한다. 동일 점수가 모두 버그라는 가설은 기각한다. 날짜별 cache/조회 버그를 고쳤다고 보고하지 않는다.

## 3. V2.1 두 층 정의

- 서식 = clamp(50 + (계절+권역+수심+지형+대상어의 기존 기여 합)×100/54, 0, 100). 52의 적합도 폭과 최대 +1 대상어를 고려한 정규화다. 날짜가 바뀌어도 같은 환경에서는 대체로 일정하고 월별 계절만 부드럽게 움직인다.
- 오늘 조건 = clamp(50 + 빛/수온/유속/조석/바람/파도의 새 기여 합, 0, 100). 모르는 조건은 0 기여, 즉 50 중립 방향이다.
- 최종 = clamp((서식×.45 + 오늘 조건×.55)×개인 기록 보정, 0, 99). 단순 평균을 검토했고, 45:55 조합만으로 극단 조건의 부적절한 고득점을 제한하므로 추가 임의 게이트를 넣지 않았다. 서식0/오늘100은 보정 전55, 반대는45이며 최대 +15% 개인 보정에도 각각63.25/51.75다.

habitatScore/dynamicScore는 소수점을 유지하고 UI만 정수로 표시한다. score/finalScore는 정수, rawScore는 제한된 소수점이다. factors.layerEffect는 층 내부 기여, factors.effect는 최종 점수 기여다. 제한이 생기면 limit 보정으로 합계를 일치시킨다. confidence/confidenceLevel은 기존 계산을 그대로 유지하며 최종점수의 곱셈 인자로 사용하지 않는다.

## 4. 날짜별 원천 검증과 미래 수온

wxAt의 실제 결과를 각 day의 biteContext와 대조했다. 메모리 전용 기상 fixture에 4개 날짜별 다른 값을 넣어 날짜 키, 12시 슬롯→14시 요청의 lagHours=2, 15시 요청 시 과거 날짜로 넘어가지 않고 null인 점을 확인한다. 운영 자료는 수정하지 않는다. BITE_CONTEXTS 수명은 한 번의 렌더이며 day/hour 키가 이미 올바르므로 불필요하게 바꾸지 않았다.

실제 tideAt의 day×24+12.5 값을 대조하고, 실제 15km 이내 KHOA 조류가 있는 포인트에서 7일의 flowU.r.sp와 crntAt을 대조한다. crntDay의 일별 최강값은 기존 flowU 안에서 같은 day를 사용한다. 15km 외삽을 하지 않는다. 실제 유속이 없으면 유속 적합도는 중립, 조석 상승/하강/정조와 조차는 작은 별도 조건이다. 조석을 조류 방향이나 입질 그 자체로 단정하지 않는다.

현재 수온은 예보가 아니며 50km·24시간 관측 필터와 미래 ahead/(48시간) 감쇠를 유지한다. 미래일수록 효과는 0으로, 신뢰도는 낮아진다. 이 감소는 미래 바다가 실제로 차가워졌다는 뜻이 아니다. 미설정 온도 범위는 계속 중립이다.

## 5. 39종 카드와 안내 문구

사진·이름·활동시간·최종점수·등급·24시간 그래프·최고시간은 유지했다. 반복 confidence 문구/아이콘은 카드에서 완전히 제거했다. 서식/오늘 조건 정수, 주 서식지, 잘 잡히는 곳을 추가했다. 이유는 현재 조건과 확인된 수심을 우선해 최대3개이며, 누락 자료/미확인 기준 같은 진단 문구를 반복하지 않는다. 상세 도움말과 진단에서만 신뢰도를 볼 수 있다. 오늘 탭은 같은 biteAt 엔진과 같은 날짜 곡선을 공유한다.

문구는 기존 ecology.group/habitat/depth 등의 넓은 생태 가정을 기본으로 작성한 일반 안내다. 어획률이나 특정 항구의 실적이 아니며 어획을 보장하지 않는다. [FishBase 우럭 생태](https://fishbase.se/Ecology/Sebastes_schlegelii), [우럭 서식 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC4556453/), [FishBase 숭어](https://www.fishbase.se/summary/Mugil_cephalus.html), [FAO 두족류 도감](https://www.fao.org/docrep/014/i1920e/i1920e.pdf)의 정성적 서식 특성도 참고했다. 모든 39종 문구가 이 문헌에서 개별 검증되었다는 주장은 하지 않는다. 포인트 유형은 서식 특성을 낚시 지형으로 풀어 쓴 해석이다. 불명확한 바닥은 단정하지 않았으며 우럭/조피볼락 문구는 공유한다.

## 7. 성능과 회귀

최종 단독 실행에서 동일 자료·시각으로 두 화면을 측정했다. renderBite 8회 측정의 중앙값/최댓값이며 한 번의 로컬 실행이라 차이를 통계적 성능 개선으로 해석하지 않는다.

| 화면 | V2 중앙/최대(ms) | V2.1 중앙/최대(ms) | 첫 카드 높이 전/후(px) |
|---|---|---|---|
| 390×844 | 25/72 | 27/74 | 329.6/400.1 |
| 1280×900 | 24/70 | 27/74 | 315.4/403.0 |

전체25개 검사 통과(실패0). 기존 V2 318개 검사를 포함한 V2.1 440개 검사가 휴대폰·PC 각각 통과했다. confidence 내부29개 검사, 사진·수집기·수심·P3·smoke/degradation 등 원본 회귀도 통과했다. 팬 이동/지도 스트레스는 각각16개 화면·배율 조합, 지도 렌더링 성능은12개 조합을 원본 반복수와 native RAF/performance로 검사했다. 전체 결과는 BITE_V21_TEST_RESULTS.json에 있다.

390×844와1280×900 다섯 탭을 직접 확인했고, 최종 카드 이미지도 확인했다. 설명 두 줄과 보조점수로 첫 카드 높이는 늘었지만 잘림·가로 넘침·하단 가림이 없고 사진·현재/최고 점수·활동시간·그래프를 유지했다. 빌드 missing ids: [], 플랫폼 빌드 일관성과 마지막 smoke도 확인했다.

실제 UI는 선택한 하루×39종×24시간만 계산한다. 전체7일 계산은 진단에서만 실행한다. 기존 환경/기상/수온/조석/조류 context 재사용과 같은 날짜 오늘 탭 곡선 공유를 유지했다. 불필요한 API 호출은 추가하지 않았다. 물리 휴대폰/실 NAVER 네트워크 성능 검증으로 해석하지 않는다.
