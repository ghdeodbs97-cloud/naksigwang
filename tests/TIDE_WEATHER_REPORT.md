# 다섯 탭 화면 밀도와 7일 예보

## 원인과 변경

- 기존 모바일 `.fishGrid`는 명시적 2열, 공통 패널 14~18px 여백과 큰 제목을 사용했다.
  강제 화면 줌을 사용하지 않고 각 탭 글자·여백을 줄였다. 휴대폰 4열, PC 6열 카드로 바꾸고
  상세 조건을 펼치면 카드가 한 줄 전체를 사용해 서식지·설명을 읽을 수 있게 했다.
- 오늘 추천 어종의 큰 `XX점` 표시는 `입질 확률` + 높음/보통/낮음으로 변경했다.
  실제 포획 확률이 아닌 조건 지수라는 안내와 원래 39종 점수 모델은 유지한다.
- 기존 기상 수집은 VEC/WSD/WAV만 저장했다. REH 상대습도를 선택적 4번째 값으로 수집하고,
  이전 3개 값 자료도 읽는다. data/ 파일은 손으로 수정하지 않았다.
- 단기예보에 없는 날짜·항목을 과거 값으로 복사하지 않고 7일 보완 모델로 표시한다.
  현재 날짜부터 7개 날짜를 노출해 새벽 갱신 전에도 어제 때문에 한 칸이 줄지 않게 했다.
- 주문진은 기존 199개 KHOA 조류 지점 중 가장 가까운 지점도 약 201km 떨어져 있었다.
  15km 적용 범위 밖이므로 수치 부재는 지점 범위 문제이며 범위를 임의로 넓히지 않았다.
  가까운 지점은 KHOA 예보를 우선하고, 없는 위치는 별도의 **해류 모델**로 보완한다.
  해류 모델로 KHOA 물돌이·최강 시각을 만들어내지 않는다. 지도 흐름·입질 계산은 바꾸지 않았다.

## 보완 예보

[Open-Meteo 기상](https://open-meteo.com/en/docs)과
[해양 API](https://open-meteo.com/en/docs/marine-weather-api)를 선택한 포인트 좌표로 조회한다.
풍향·풍속·습도, 파고·해수면 수온·해류 방향/속도의 7일 시간별 자료를 사용한다.
API 제공 격자가 25km를 넘게 떨어지면 거부한다. 실제 격자/예보 지점 거리를 표시한다.
기상청 값이 있으면 우선하고 부족한 항목만 보완한다. 미래 수온은 해수면 모델로 명시하며
현재 KHOA 관측을 복사하지 않는다. 모델의 연안 약 8km 해상도는 정밀 갯바위 조류가 아니다.

한 포인트에 두 요청, 같은 날짜/시각 전환은 캐시 재사용. 최대 8개 포인트·30분 메모리 캐시,
실패 시 1분 재요청 제한, 12초 요청 중단. 두 API 중 하나가 실패해도 다른 자료와 기존 앱은 유지한다.
KST·시간 배열·좌표·단위를 검사하고 km/h 해류는 m/s로 변환한 뒤 kn 표시로 변환한다.
결측과 유효한 0을 구분하며, 알 수 없는 수치나 단위를 0으로 대신하지 않는다.
조회 시각은 모델 발표 시각으로 표시하지 않는다.

선택 포인트 좌표가 외부 API에 전달됨을 기록 탭 출처에 표시했다. 인증키는 사용하지 않는다.
CC BY 4.0 출처 링크를 추가했다. [무료 API 조건](https://open-meteo.com/en/terms)은
비상업용·일 10,000 / 시간 5,000 / 분 600회 미만이다. 현재 개인 테스트용으로 사용하며,
광고·유료·상업 출시 전에는 유료 API 계약과 키를 앱에 노출하지 않는 서버 중계 구성이 필요하다.
이 작업에서 결제·구독·스토어 제출·배포 merge를 수행하지 않는다.

## 검증

`tests/test_tide_weather_ui.py`는 외부 요청을 모두 mock으로 바꿔 검사한다.
수정 전 390px 2열·습도 표시 없음 재현 후, 390×844 / 320×740 4열과 1280×900 6열을 검증한다.
다섯 탭 가로 넘침·화면 캡처, 상세 열기, 오늘 문구, 7일 값, 미래 수온 모델 구분,
KHOA 우선, km/h 변환, 잘못된 단위·UTC·먼 격자 거부, 날짜 전환 추가 요청 0,
기존 점수 불변, 압축 미지원, 외부 실패/결측 복구를 검사한다.
수집기 회귀에 새 4항목과 이전 3항목의 동시 지원 검사를 추가했다.

실 API는 개발 중 주문진 1곳에 두 번만 비인증 조회해 168시간 응답과 단위를 확인했다.
실사용자의 기기·네트워크 검증은 별도다. 테스트 화면의 일정한 예보 수치는 mock 값이다.
data/, static/depth/, 04_depth.js, 04b_depth_tiles.js, 18_section.js는 변경하지 않는다.

지도 20개 viewport/DPR와 6개 SDK 실패 검사는 통과했다. 기존 baseline의 해양 수심 조회 전체와
301개 단면 좌표·수심·datum/provenance hash도 동일했다. 다만 여백 변경으로 화면 중앙 hover가
경도 129.10840에서 129.08491로 옮겨져 육지 표고 표시만 달랐다. `p3_baseline.py`의 hover 입력을
기존 baseline의 고정 경위도(35.85301, 129.10840)로 지정해 같은 장소를 비교하도록 수정했다.
기존 baseline JSON이나 허용오차, 수심·지도 코드는 바꾸지 않았다.
