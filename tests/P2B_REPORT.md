- 공식 안내 확인: 연안해역기본도는 1:25,000/50 m 이내/전국이며 조사 시기 2010~2017 포함. 원본 다운로드는 로그인·전용 전송 프로그램 필요. SHP 설명과 DXF 확장자 표기가 달라 파일 확보 후 실제 형식을 확인해야 한다.
- BADA: 공식 설명상 150 m 격자/JSON·XML, 기존 범위 API를 유지. 인증된 실제 응답이나 원본 파일은 새로 확보하지 않았다.
- GEBCO 2026: 공식 15 arc-second 격자/기준면 가정 및 TID 문서 확인. 기존 저장소 한국 영역 격자를 유지했고 새 원본을 내려받거나 변경하지 않았다.
- **실제 앱 추가 자료: 빈 manifest 39 bytes, 수심 타일 0개.** 준비만 된 자료: 연안해역기본도/해수부 수심 원본/공개 해도/BADA의 지역 타일 provider. TID는 구조·비용만 검토하고 미탑재.
- 사용자 필요 파일: `tools/depth-data/raw/ngii/<도엽>/`의 SHP+SHX+DBF+PRJ(+CPG), 도엽 설명/조사연도/기준면/간격. DXF면 검증 후 QGIS GeoJSON 내보내기. 해수부는 수심 속성이 포함된 별도 원본과 CRS 정의가 필요하다. 정확한 절차·필수 옵션·형식은 [데이터 준비 README](../tools/depth-data/README.md).

## 구현과 모바일 비용

지역 단위 JSON(0.1도, 12,000점/1 MiB 이하) + manifest 출처사전 + 1,000 Mercator m 색인. 지역을 떠나면 캐시를 해제한다. 순차 요청 1개, 캐시 12타일/60,000점/JSON 8 MiB 제한이며 초과하면 부분 자료를 쓰지 않고 확대 시 로드한다. 파일/목록 요청은 8초·크기 제한을 갖고 실패해도 기존 fallback으로 부팅한다. 인접 타일을 해상도 검색반경만큼 준비하여 경계의 후보를 포함한다.

추가 수심 데이터 전송은 현재 manifest 39 bytes뿐. 기존 GEBCO JS 2,591,809 bytes는 그대로이고, 해제된 고도+음영 배열은 7,566,912 bytes(앱 전체 heap 수치 아님)다. 앱 코드는 수심 schema/로더/상세 표시만큼 증가했다. **실자료 없이 고밀도 전국 서비스의 모바일 성능이 검증됐다고 주장하지 않는다.** JSON 제한은 총 JS heap 제한과 다르다. 첫 로딩은 manifest만 요청하며 전국 SHP/CSV를 모바일에 적재하지 않는다.

공통 source schema는 `depth, sourceType, source, resolution, distanceToSource, interpolated, estimated, confidence, confidenceReason, verticalDatum, surveyYear, measurementCount`. 기존 `type/label/res/dist/n/conf/interp/src/yr`를 유지한다. 기여한 원본 연도/해상도/거리도 `contributingSources`에 보존. 미확인 기준면은 unknown·낮음. 개인 CSV 입력은 crowd_pending이며 검수 완료 자료로 자동 승격하지 않는다. 공식 타일은 coastal_official/mof_contour/chart_public/bada만 받는다. user_verified/crowd_verified는 향후 검수 provider 확장용이고 현재 구현된 서버 검수가 아니다.

같은 자료집·기준면 안에서만 역거리제곱 보간. GEBCO/가정값을 섞지 않으며 단면의 서로 다른 자료집·기준면 경계에서는 해저선 연결과 지형 특징 판정을 중단한다. 배경 색/등심선은 해안거리 근사값을 포함하므로 위치 조회와 다를 수 있음을 화면에 밝힌다. `crossesLand`는 지도 좌표·약 5 m 샘플 판정으로 viewport 의존을 제거했고, 모두 바다인 단면은 가짜 해안·캐스팅 기준점을 만들지 않는다.

## 미래 연결

사용자 실측은 원측정 ID/좌표/시각/방법/좌표 오차/캐스팅 거리·방향/조위 보정/보정 수심/사진 참조/메모/계정/검수/생성·수정시각을 별도 레코드로 보존한다. 중앙값·robust mean·이상치·측정방식·횟수·공식자료 차이에 쓸 필드를 정의했으며 실제 집계는 미구현.

현장사진은 영구 pointId 레지스트리와 measurement ID로 연결한다. 현재 POINTS 배열 인덱스는 영구ID로 쓰지 않는다. 관찰 방향·캐스팅 위치·설명·측정일·검수를 보존하며 사진으로 수심을 추정하는 기능은 없다. [future-records.md](../tools/depth-data/future-records.md).

위성지도 추가 시 수심엔진과 A/B 분석은 유지하고 `scheduleDepthArea`의 viewport→경위도 범위, 입력 좌표 어댑터, Canvas 배경/레이어를 교체한다. `depthPrepareAreas`는 경위도 범위만 받고 수심 선택/보간은 지도 표현을 모른다.
