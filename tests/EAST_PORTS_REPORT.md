# 동해 항·선착장 세분화

## 원인과 범위

기존 BASE_PORTS716개 중 동해 선택 항은30개였다. 실제 검사에서 이30개는 모두 선택되고 있어, 기존 항이5km 필터 때문에 빠진 사례는 없었다. 핵심 누락은 어항 CSV에 없는 주문진·속초 등의 연안항/무역항 이름이 OSM 지도 검색에는 있으나 POINTS에 연결되지 않은 점이었다. 항구 존재와 구분은 [동해지방해양수산청 관할구역](https://donghae.mof.go.kr/ko/page.do?menuIdx=2633), [포항지방해양수산청 후포항 안내](https://pohang.mof.go.kr/ko/page.do?menuIdx=2803)도 참고했다. 새 위치를 외부 검색 결과에서 추측해 만들지 않았다.

기존 대표점을 보존한 뒤 동해에만34개를 추가해 항·선착장30→64개, 동해 전체 포인트(갯바위 포함)127→161개, 전국 전체606→640개다. 다른 해역은 기존5km 대표점 정책을 유지한다. 남해243/서해184/제주52개 포인트의 이름·좌표·순서가 동일하고 모든 기존 갯바위도 동일하다.

## 출처와 중복 처리

추가32개는 기존 static/osm.js의 이름 위치다. 묵호·후포2개는2026-10-31 data/tide.json에 들어 있던 국립해양조사원 조석 지점 좌표를 대표 위치로 보존한다. 일시적인 일별 예보 누락으로 항구가 사라지지 않도록 좌표를 별도 보존했다. 대표 위치는 항만 출입구·개별 방파제 위치나 낚시 허용 확인이 아니다. 기록 탭의 OSM/KHOA 출처 표시를 유지·보완했다.

공항·호텔·항공시설·크루즈 상호·별표 미확인 이름은 후보에서 제외한다. 같은 기본 이름이1km 안에 겹치면 합치고 항 이름을 선착장/나루터보다 우선한다. 속초항과 동명항처럼 서로 다른 이름은5km 안에서도 둘 다 유지한다. 멀리 떨어진 같은 이름의 후진항 등은 예보 지점을 덧붙여 드롭다운/검색에서 구분한다. 주요 항은 광역 축척에서도 지도 표시 대상으로 둔다.

## 예보 범위

collector/points.json 수집 대상을615→628개 기상 격자로 보강했다. 기존615개·조석166지점·관측55지점은 보존했다. CI 동해 항구 검사에서 모든 동해 항 좌표의 기상 격자가 수집 설정에 들어 있는지 확인한다. collector/collect.py나 data/는 수정하지 않았다.

현재 저장된 기상자료615개에는 포항구항·포항영일신항만·독도항·독도 구나루터·서도나루터의 가까운 격자가 없다. 현재 시각 검사에서는640포인트 중 바람/파고635곳, 수온628곳이 유효했다. 수온은 기존50km/24시간 조건을 유지한다. 빈 기상값은 만들어 넣지 않고 화면에는 격자 누락과 예보 시각 누락을 구분한다. 늘린628개 수집 설정은 현재 feature에 있으며, main에서 이 설정을 쓰는 수집이 실행되기 전에는 새 격자값이 생겼다고 주장하지 않는다.
